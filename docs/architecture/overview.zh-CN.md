# 架构总览

> featcache：一次加载，多进程零拷贝共享，热切换。

> 本文件是 [overview.md](overview.md)（英文版）的中文翻译。英文版为权威版本。

## 1. 系统目标

**featcache** 是一个面向 AI 推理场景的零拷贝运行时数据缓存。它解决的核心问题是：

> AI 推理进程启动时，大量静态数据（Embedding、Tokenizer、Feature Dictionary 等）的重复加载导致启动慢、资源浪费。

传统方案下，N 个推理进程各自加载一份 10GB+ 数据：

- 启动延迟数分钟
- 内存占用 N × 数据量
- 每次进程重启都要重新加载

featcache 将数据**加载一次**，写入共享内存，所有进程通过 `mmap` 读取同一份物理内存。

## 2. 角色定义

```
┌──────────────────────────────────────────────────────────┐
│                featcache 守护进程 (featload)              │
│                = Loader / Artifact Manager               │
│                                                          │
│  ▲ 唯一写入者 (Single Writer)                             │
│  ▲ 从数据源加载推理工件                                    │
│  ▲ 写入共享内存段，构建哈希索引                             │
│  ▲ 通过 UDS 提供控制面服务                                 │
└──────────────┬───────────────────────────────────────────┘
               │  shm + mmap
               ▼
┌──────────────────────────────────────────────────────────┐
│                  共享内存段 (Memory Segment)              │
│                                                          │
│  ┌──────────────────────────────────────────────────┐    │
│  │  数据面 (Data Plane)                              │    │
│  │  • Header (64B)                                   │    │
│  │  • 哈希索引：开放寻址，O(1) 查找                    │    │
│  │  • 数据区域：紧凑连续存储 key + value               │    │
│  │  • 零拷贝读取，无锁，无 syscall                     │    │
│  └──────────────────────────────────────────────────┘    │
│                                                          │
│  控制面 (Control Plane) → Unix Domain Socket             │
│  • 客户端初始化时获取段元数据                              │
│  • 热切换时通知版本变更（二期）                            │
└──────────────┬───────────────────────────────────────────┘
               │  mmap（所有进程共享同一物理内存）
               ▼
┌──────────────────────────────────────────────────────────┐
│  推理进程 0    推理进程 1    推理进程 2  ...  推理进程 N    │
│                                                          │
│  ▲ 只读访问 (PROT_READ)                                   │
│  ▲ 直接读内存段，零拷贝                                    │
│  ▲ 查询延迟 ≈ 本地 map 读取                                │
│  ▲ 无锁，无 syscall，无 UDS 通信                          │
└──────────────────────────────────────────────────────────┘
```

### 关键原则：控制面与数据面分离

| 维度 | 控制面 (UDS) | 数据面 (共享内存) |
|------|-------------|------------------|
| 用途 | 初始化、元数据、版本通知 | 所有数据读取 |
| 频率 | 进程启动时一次 | 每次查询 |
| 延迟 | 微秒级（可接受） | 纳秒级 |
| 协议 | 自定义二进制协议 | 无（直接内存访问） |

## 3. 组件职责

| 组件 | 文件 | 职责 |
|------|------|------|
| `Segment` | `segment.go` | 共享内存段的创建/打开/关闭/销毁，平台无关接口 |
| `Segment (linux)` | `segment_linux.go` | Linux mmap 实现（`/dev/shm` + `unix.Mmap`） |
| `Segment (other)` | `segment_other.go` | 非 Linux 桩（返回 `ErrNotSupported`；内存段 close/destroy 供测试） |
| `HashTable` | `hashtable.go` | 开放寻址 + 线性探测哈希表，CAS 写入，原子读 |
| `HashKey` | `hash.go` | `hash/maphash` 64-bit 哈希 |
| `Loader` | `loader.go` | 唯一写入者：读数据源、写段、构建索引 |
| `Reader` | `reader.go` | 零拷贝读取者：直接查共享内存哈希表 |
| `CacheServer` | `server.go` | UDS 控制面服务器（`OpGetInfo` / `OpGetStatus`） |
| `DataSource` | `datasource.go` | 数据源抽象 + 内置实现（文件/行/Map） |
| 协议编解码 | `protocol.go` | UDS 二进制协议编码/解码 |
| `featload` | `cmd/featload/` | Loader 守护进程入口 |

## 4. 数据流

### 4.1 加载流程（写入路径）

```
Loader 启动
  │
  ├─ 1. 创建/打开共享内存段 (shm_open + mmap)
  ├─ 2. Init(n)：根据预估条目数计算哈希表大小，初始化 Header + 哈希表
  ├─ 3. Load(ds) 内部调用 ds.Open() → totalEntries
  ├─ 4. 循环读取 (ds.Next())：
  │      ├─ 写入数据区 [keyLen:4B][key][value]
  │      ├─ 原子推进 data_end
  │      └─ 插入哈希表 slot（数据先就绪，slot 后标记）
  ├─ 5. GenCounter++ 发布新版本
  └─ 6. 就绪，监听 UDS
```

### 4.2 读取流程（查询路径）

```
推理进程启动
  ├─ 1. 连接 UDS
  ├─ 2. GET_INFO → 获取段名称、大小、布局
  ├─ 3. mmap 共享内存段
  ├─ 4. 关闭 UDS 连接（后续不再使用）
  └─ 5. 查询：GET(key) 直接在共享内存哈希表中查找
```

> **当前实现说明**：`Reader.connect` 目前直接打开段；GET_INFO 交换是规划的 TODO（见 [roadmap](../design/roadmap.md)）。

### 4.3 请求生命周期

```
Reader.Get(key):
  1. hash = HashKey(key)                       // 本地计算
  2. idx = hash & (hashCap - 1)                // 定位 slot
  3. 循环探测：
       slot.status == empty  → NOT_FOUND
       slot.status == used && slot.hash == hash
         && key 匹配          → 返回 value     // 指向共享内存
  4. 全过程：无锁，无 syscall，无 UDS 通信
```

## 5. 扩展点

| 扩展点 | 接口/位置 | 说明 |
|--------|----------|------|
| 数据源 | `DataSource` 接口 | 实现文件、数据库、对象存储等任意数据源 |
| 值格式 | 无限制 | Value 是不透明字节序列，调用方定义序列化 |
| 协议 OpCode | `types.go` | 预留 WATCH/PIN/PREFETCH/EVICT/LIST/RELOAD（二期/三期） |
| 热切换 | 二期 | 双缓冲 + 原子指针切换 |

## 6. 性能考虑

| 指标 | 目标 | 关键设计支撑 |
|------|------|-------------|
| 启动延迟 < 100ms | 无论数据量 | 只需 mmap + 一次 UDS 查询 |
| 查询延迟 < 100ns | 单次 Get | 无锁原子读 + hash 比较，无 syscall |
| 内存效率 ~1.002× | 数据量 | 紧凑存储，无内部碎片 |
| 多进程内存节省 (N-1)× | N 进程 | 共享同一物理内存 |

性能瓶颈只在写入路径（一次性），读取路径为纯内存访问。

## 7. 安全考虑

| 风险 | 缓解措施 |
|------|---------|
| 共享内存段名称冲突 | 唯一段名 + `O_EXCL` 创建 |
| 段权限 | 0600 文件权限，仅同用户进程可访问 |
| 越界读 | 哈希表/读取路径均有边界检查 |
| UDS 越权访问 | 生产环境建议配合文件系统权限；抽象命名空间仅同用户可连 |
| 写入者崩溃 | 段保留在 `/dev/shm`，重启后可复用（可用 `destroy` 清理） |

更多安全内容见 [SECURITY.zh-CN.md](../../SECURITY.zh-CN.md)。
